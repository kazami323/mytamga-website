# Выкладка сайта на ahost (тариф «Микро»)

Схема: **сайт** — на общем хостинге ahost, тариф «Микро» (cPanel, Node.js);
**API приложения** — на VPS в eskiz.uz. Браузер посетителя обращается только к
сайту, а сайт сам обращается к API.

Тариф подходит по всем числам: пакет сайта весит ~66 МБ (диск 1 ГБ), это
~1 600 файлов (лимит 50 000), сервер занимает ~106 МБ памяти (лимит 1 ГБ).
Проверено пробным запуском собранного пакета.

---

## Что нужно один раз

### 1. Секретный ключ сайта

Сайт стоит на общем хостинге, и API видит не адрес посетителя, а адрес сервера
ahost — общий с чужими сайтами. Чтобы лимит на вход по SMS считал каждого
посетителя отдельно, сайт передаёт API адрес посетителя вместе с секретным
ключом, и API верит адресу только при совпадении ключа.

Сгенерировать ключ на своём компьютере:

```bash
openssl rand -hex 32
```

Одно и то же значение задаётся в двух местах:
- на сайте — переменная `MYTAMGA_API_PROXY_KEY` (шаг 4 ниже);
- в API — переменная `SITE_PROXY_KEY` (см. `docs/API_SITE_PROXY_KEY_RU.md`).

Ключ — как пароль: не присылать в чатах, не коммитить.

### 2. Адреса в DNS

| Запись | Куда | Зачем |
| --- | --- | --- |
| `mytamga.uz` и `www` | хостинг ahost | сайт |
| `api.mytamga.uz` | IP вашего VPS в eskiz.uz | API приложения |

Если домен обслуживается ahost, запись `api` добавляется в cPanel →
«Редактор зон» (Zone Editor): тип A, имя `api`, значение — IP VPS.

### 3. HTTPS

cPanel → «Статус SSL/TLS» → запустить AutoSSL для `mytamga.uz` и
`www.mytamga.uz`. Без HTTPS вход на сайте работать не будет: куки сессии
помечены как защищённые и по обычному HTTP не передаются.

## Сборка пакета — на своём компьютере

На хостинге собирать нельзя: зависимости весят 519 МБ, а сборке не хватит 1 ГБ
памяти. Пакет собирается локально:

```bash
NEXT_PUBLIC_SITE_URL=https://mytamga.uz \
MYTAMGA_API_URL=https://api.mytamga.uz \
npm run package:ahost
```

Получится `dist/mytamga-site.zip` (~20 МБ).

Скрипт откажется собирать без этих адресов или с `localhost`: адрес сайта
вшивается в страницы при сборке — из него строятся ссылки для поисковиков и
адрес картинки-превью. Если API в момент сборки недоступен, скрипт
предупредит: сайт соберётся, но страница тарифов первый час покажет «цены
временно недоступны», а потом обновится сама.

## Выкладка в cPanel

### 4. Создать приложение Node.js

cPanel → «Программное обеспечение» → **Setup Node.js App** → «Создать
приложение»:

| Поле | Значение |
| --- | --- |
| Node.js version | 22 или 24 (нужна 20.9 и выше) |
| Application mode | Production |
| Application root | `mytamga-site` |
| Application URL | `mytamga.uz` |
| Application startup file | `server.js` |

В блоке переменных окружения добавить:

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` |
| `MYTAMGA_API_URL` | `https://api.mytamga.uz` |
| `MYTAMGA_API_PROXY_KEY` | ключ из шага 1 |
| `NEXT_PUBLIC_SITE_URL` | `https://mytamga.uz` |

Сохранить. Кнопку «Run NPM Install» **не нажимать**: все нужные зависимости
уже лежат в пакете.

### 5. Загрузить и распаковать

cPanel → «Диспетчер файлов» → открыть папку `mytamga-site` → загрузить
`mytamga-site.zip` → «Извлечь» в эту же папку. В корне должны оказаться
`server.js`, `package.json`, папки `.next`, `public`, `node_modules`.

Папка `.next` начинается с точки — в диспетчере файлов включите «Показывать
скрытые файлы», иначе её не видно.

### 6. Запустить

Вернуться в Setup Node.js App → у приложения нажать **Restart**.

## Если cPanel ругается на node_modules

На многих хостингах раздел Setup Node.js App сделан на CloudLinux, и он хранит
зависимости в отдельной папке, а в корне приложения создаёт ссылку
`node_modules` на неё. Тогда при сохранении может появиться сообщение вроде:
«application should not contain folder/file with such name (node_modules)».

Что делать:
1. Удалить из `mytamga-site` распакованную папку `node_modules`.
2. В настройках приложения посмотреть путь виртуального окружения — он
   показан вверху, вида `/home/<логин>/nodevenv/mytamga-site/22/…`.
3. Загрузить содержимое `node_modules` из архива в папку
   `…/nodevenv/mytamga-site/<версия>/lib/node_modules`.
4. Restart.

Проверить это отсюда нельзя — доступа к вашему cPanel у меня нет. Если упрётесь
в другое сообщение, пришлите его текст.

## Проверка после выкладки

1. `https://mytamga.uz` открывается и переводит на язык браузера
   (`/ru`, `/uz`, `/en` или `/zh`).
2. Подвал на месте: реквизиты, оферта, политика, условия, поддержка.
3. Ссылка на сайт, отправленная в Telegram, показывает превью с логотипом.
4. Когда API поднят: на `/ru/pricing` видны тарифы, вход по номеру присылает SMS.
5. Сверка цен на живом сайте — со своего компьютера:

   ```bash
   SITE_URL=https://mytamga.uz MYTAMGA_API_URL=https://api.mytamga.uz npm run check:catalog
   ```

6. Лимит входа считает посетителей отдельно: запросите код с телефона через
   мобильный интернет и с компьютера через Wi-Fi — в журнале API должны быть
   два разных адреса, а не адрес сервера ahost. Если адрес один и тот же,
   ключ на сайте и в API не совпадает или API ещё не принимает его.

---

## Обновление сайта

Собрать новый пакет (раздел «Сборка пакета»), загрузить, распаковать поверх
старого с заменой файлов, нажать Restart.

---

## Что не заработает до API

Главная, юридические страницы, контакты и подвал работают и без API. Без него:
- на странице тарифов — «цены временно недоступны»;
- вход по номеру и оплата недоступны.

И отдельно от API: **форма заявки на главной никуда не отправляет** — она
честно пишет, что приём заявок не подключён. Канал (Telegram, почта, CRM) ещё
не выбран.
