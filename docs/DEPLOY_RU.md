# Деплой MyTamga: сайт на ahost, API на eskiz.uz

Полная инструкция запуска. Составлена 2 октября 2026 по коду обоих
репозиториев и проверена пробным запуском собранного сайта. Если что-то здесь
расходится с кодом — верить коду и поправить этот файл.

---

## Схема

```
посетитель ──► https://mytamga.uz           ahost, тариф «Микро»
                 сайт (Next.js, Node.js)     cPanel → Setup Node.js App
                      │
                      │ HTTPS + секретный ключ сайта
                      ▼
               https://api.mytamga.uz        VPS в eskiz.uz
                 Caddy → API (NestJS)        Docker: deploy/ahost
                         → PostgreSQL, Redis

мобильное приложение ──► https://api.mytamga.uz   напрямую
```

- Браузер посетителя обращается **только к сайту**. Вход по SMS, чтение
  подписки, оплату сайт выполняет сам, запросом к API. Поэтому CORS для сайта
  настраивать не нужно.
- Токены входа живут в куках `HttpOnly` на `mytamga.uz` — для этого обязателен
  HTTPS на сайте.

| Что | Где | Репозиторий |
| --- | --- | --- |
| Сайт | ahost, тариф «Микро» | `kazami323/mytamga-website` (приватный) |
| API, база, Redis | VPS в eskiz.uz | репозиторий приложения MyTamga, `apps/api` и `deploy/ahost` |

Папка `deploy/ahost` в репозитории приложения называется так исторически: это
сборка под любой Ubuntu-VPS с Docker. Для VPS в eskiz она подходит как есть.

---

## Порядок работ

Порядок важен: каждый шаг опирается на предыдущий.

1. Сгенерировать секреты.
2. Внести в API правку «ключ сайта» — без неё вход на сайте работает, но лимит
   SMS считает всех посетителей как одного.
3. Поднять API на VPS eskiz.
4. DNS: `api.mytamga.uz` → VPS, `mytamga.uz` → ahost.
5. Выложить сайт на ahost.
6. Включить HTTPS на сайте.
7. Проверить по чек-листу.

Сайт можно выложить и **до** API: главная, контакты, юридические страницы и
подвал работают без него. Без API на странице тарифов будет «цены временно
недоступны», а вход и оплата не заработают.

---

## 1. Секреты

| Секрет | Где задаётся | Как получить |
| --- | --- | --- |
| Ключ сайта | на сайте `MYTAMGA_API_PROXY_KEY`, в API `SITE_PROXY_KEY` — **одно и то же значение** | `openssl rand -hex 32` |
| Секреты API (`JWT_SECRET`, `POSTGRES_PASSWORD` и др.) | `deploy/ahost/.env.production` на VPS | по `docs/LAUNCH_CHECKLIST_RU.md` репозитория приложения, шаг 3 |
| Ключи Click | `deploy/ahost/.env.production` на VPS | от Click после подключения мерчанта; пока их нет — оставить пустыми |

Секреты не коммитить и не пересылать в чатах. На сайте ни одного секрета в
коде нет: ключ сайта задаётся в cPanel и в сборку не попадает.

---

## 2. Правка в API: ключ сайта

**Зачем.** Сайт на общем хостинге, и API видит не адрес посетителя, а адрес
сервера ahost — общий с чужими сайтами. Лимит входа (`AUTH_RATE_LIMIT_MAX`
запросов на адрес) начнёт считать всех посетителей сайта как одного: при
пороге 3 в минуту четвёртый человек получит отказ. Добавить адрес ahost в
`TRUST_PROXY` нельзя — соседи по хостингу смогли бы подделать адрес.

**Что.** API принимает адрес посетителя из заголовка `x-site-client-ip`, только
если `x-site-proxy-key` совпадает с `SITE_PROXY_KEY`. Готовый код, места
подключения и тесты — в **`docs/API_SITE_PROXY_KEY_RU.md`** этого репозитория.
Около тридцати строк в двух guard-ах и в конфиге.

Сайт уже отправляет оба заголовка, как только ему задан ключ.

## 3. API на VPS eskiz.uz

Основная инструкция — в репозитории приложения, её не пересказываю, чтобы не
разойтись с ней:

- `docs/LAUNCH_CHECKLIST_RU.md` — шаги 1–6: сервер, домен, секреты, запуск,
  приложение, резервные копии;
- `deploy/ahost/README_RU.md` — скрипты `bootstrap-ubuntu.sh`, `deploy.sh`,
  `check.sh`.

Кратко по VPS: Ubuntu, root-доступ по SSH, порты 80 и 443 открыты. Чек-лист
приложения просит 2 ядра, **4 ГБ** памяти и 40 ГБ диска.

```bash
sudo bash bootstrap-ubuntu.sh
cd deploy/ahost && cp .env.production.example .env.production   # заполнить
./deploy.sh && ./check.sh
```

### Что в `.env.production` важно именно для сайта

| Переменная | Значение | Почему |
| --- | --- | --- |
| `API_DOMAIN` | `api.mytamga.uz` | Caddy выпускает на него сертификат |
| `SITE_PROXY_KEY` | ключ сайта из шага 1 | после правки из шага 2 |
| `CLICK_RETURN_URL` | **`https://mytamga.uz/pay/return`** | в примере стоит `https://api.mytamga.uz/billing/success` — это неверно: страница возврата после оплаты живёт на сайте и спрашивает у API статус платежа |
| `TRUST_PROXY` | оставить пустым | по умолчанию API доверяет Caddy на той же машине — так и нужно |
| `CORS_ORIGINS` | как в примере | сайту CORS не нужен, браузер к API не ходит |

### Проверка API

```bash
curl https://api.mytamga.uz/health
curl https://api.mytamga.uz/api/billing/plans
```

Первый — `{"ok":true,...}`, второй — список из четырёх тарифов.

## 4. DNS

| Запись | Тип | Значение |
| --- | --- | --- |
| `api.mytamga.uz` | A | IP VPS в eskiz |
| `mytamga.uz` | A | IP хостинга ahost (обычно выставлен, если домен подключён к хостингу) |
| `www.mytamga.uz` | CNAME или A | на `mytamga.uz` |

Если домен обслуживается ahost: cPanel → «Редактор зон» (Zone Editor) →
добавить A-запись `api`.

## 5. Сайт на ahost

Тариф «Микро» подходит по всем числам: распакованный сайт — ~66 МБ (диск
1 ГБ), ~1 600 файлов (лимит 50 000), сервер занимает ~106 МБ памяти (лимит
1 ГБ). Node.js в cPanel — до 24-й версии, нужна 20.9 и выше.

### 5.1. Взять готовый пакет

Готовый архив лежит в **Releases** репозитория `kazami323/mytamga-website` —
файл `mytamga-site.zip` в последнем релизе вида `site-v…`. Он собран с
адресами `https://mytamga.uz` и `https://api.mytamga.uz`, без секретов.

Собирать заново нужно, если:
- поменялся код сайта;
- поменялся адрес сайта или API;
- API заработал после сборки, а цены на странице тарифов нужны сразу, а не
  через час (страница тарифов собирается заранее и обновляется раз в час).

### 5.2. Собрать пакет самому

На хостинге собирать нельзя: зависимости весят 519 МБ, а сборке не хватит
1 ГБ памяти. Собирать на своём компьютере, Node.js 20.9+:

```bash
git clone https://github.com/kazami323/mytamga-website.git
cd mytamga-website
git checkout <тег релиза или ветка, которую сказали выкладывать>
npm ci

NEXT_PUBLIC_SITE_URL=https://mytamga.uz \
MYTAMGA_API_URL=https://api.mytamga.uz \
npm run package:ahost
```

Получится `dist/mytamga-site.zip`. Скрипт откажется собирать без этих двух
адресов или с `localhost`: адрес сайта вшивается в страницы при сборке — из
него строятся ссылки для поисковиков и картинка-превью ссылки. Если API в
момент сборки недоступен, скрипт предупредит и всё равно соберёт.

Перед сборкой можно прогнать проверки:

```bash
npm test            # тесты логики
npm run typecheck
npm run lint
```

### 5.3. Создать приложение в cPanel

cPanel → «Программное обеспечение» → **Setup Node.js App** → «Создать
приложение»:

| Поле | Значение |
| --- | --- |
| Node.js version | 22 или 24 |
| Application mode | Production |
| Application root | `mytamga-site` |
| Application URL | `mytamga.uz` |
| Application startup file | `server.js` |

Переменные окружения (блок Environment variables):

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` |
| `MYTAMGA_API_URL` | `https://api.mytamga.uz` |
| `MYTAMGA_API_PROXY_KEY` | ключ сайта из шага 1 |
| `NEXT_PUBLIC_SITE_URL` | `https://mytamga.uz` |

Сохранить. Кнопку **Run NPM Install не нажимать**: все зависимости уже в
архиве.

### 5.4. Загрузить и запустить

1. cPanel → «Диспетчер файлов» → включить «Показывать скрытые файлы» (папка
   `.next` начинается с точки).
2. Открыть `mytamga-site` → загрузить `mytamga-site.zip` → «Извлечь» сюда же.
3. В корне должны оказаться `server.js`, `package.json`, `.next`, `public`,
   `node_modules`.
4. Setup Node.js App → у приложения **Restart**.

### 5.5. Если cPanel ругается на node_modules

Раздел Setup Node.js App на многих хостингах сделан на CloudLinux: он держит
зависимости в отдельной папке, а в корне приложения создаёт на неё ссылку
`node_modules`. Тогда возможно сообщение вида «application should not contain
folder/file with such name (node_modules)».

1. Удалить из `mytamga-site` распакованную папку `node_modules`.
2. В настройках приложения найти путь виртуального окружения — вида
   `/home/<логин>/nodevenv/mytamga-site/<версия>/`.
3. Загрузить содержимое `node_modules` из архива в
   `…/nodevenv/mytamga-site/<версия>/lib/node_modules/`.
4. Restart.

Этот шаг не проверен на живом cPanel ahost — доступа не было. Если появится
другое сообщение, его текст нужен целиком.

## 6. HTTPS на сайте

cPanel → «Статус SSL/TLS» → AutoSSL для `mytamga.uz` и `www.mytamga.uz`.

Без HTTPS вход по номеру не заработает: куки сессии помечены `Secure` и по
обычному HTTP браузер их не отправит.

## 7. Проверка

| # | Что | Как | Ожидание |
| --- | --- | --- | --- |
| 1 | Сайт открывается | `https://mytamga.uz` | переводит на язык браузера: `/ru`, `/uz`, `/en`, `/zh` |
| 2 | Юридическое | подвал любой страницы | реквизиты ООО «MY TAMGA APP», ИНН; ссылки на оферту, политику, условия, поддержку открываются |
| 3 | Превью ссылки | отправить `https://mytamga.uz` в Telegram | превью с логотипом |
| 4 | Тарифы | `https://mytamga.uz/ru/pricing` | четыре тарифа (Basic, Pro, Business, VIP); у Pro и Business — «В процессе обсуждения» |
| 5 | Вход | номер `+998…` в панели «Оформление» | приходит SMS, после кода виден текущий тариф |
| 6 | Лимит считает посетителей отдельно | запросить код с телефона через мобильный интернет и с компьютера через Wi-Fi | в журнале API **два разных адреса**, а не адрес сервера ahost |
| 7 | Сверка цен | со своего компьютера, в репозитории сайта | `SITE_URL=https://mytamga.uz MYTAMGA_API_URL=https://api.mytamga.uz npm run check:catalog` → «Сверка пройдена» |
| 8 | Возврат с оплаты | `https://mytamga.uz/pay/return` | открывается, просит войти |

Если в пункте 6 адрес один и тот же — ключ на сайте и в API не совпадает, или
правка из шага 2 ещё не выложена.

## Обновление и откат

**Обновить сайт:** собрать новый пакет (5.2) или взять новый релиз → загрузить
→ распаковать поверх с заменой → Restart.

**Откатить:** держать предыдущий `mytamga-site.zip` (он есть в прошлом релизе)
→ распаковать его → Restart. Настройки и ключи в cPanel откат не трогает.

**Обновить API:** по `deploy/ahost/README_RU.md` репозитория приложения —
`git pull`, `./deploy.sh`.

## Если что-то не так

| Признак | Вероятная причина | Что делать |
| --- | --- | --- |
| На сайте ошибка 503 или пустая страница | приложение не запущено или упало | Setup Node.js App → Restart; журнал ошибок — в папке приложения или в разделе журналов cPanel (зависит от настройки хостинга) |
| «Цены временно недоступны» | API не отвечает, или сайт собран без доступа к API | проверить `curl https://api.mytamga.uz/api/billing/plans`; подождать час или пересобрать |
| Вход: «Слишком часто» у всех подряд | лимит считает всех как одного | шаг 2: ключ в API и на сайте, проверка 6 |
| Вход не держится, после кода снова просит номер | сайт открыт по HTTP | шаг 6, AutoSSL |
| Превью ссылки без картинки или ведёт на localhost | сайт собран без `NEXT_PUBLIC_SITE_URL` | пересобрать с адресом (5.2) |
| Ошибка про `node_modules` при сохранении приложения | CloudLinux в cPanel | раздел 5.5 |
| После оплаты Click возвращает не на сайт | неверный `CLICK_RETURN_URL` в API | шаг 3: `https://mytamga.uz/pay/return` |

## Что ещё не готово — это не ошибки деплоя

- **Форма заявки на главной никуда не отправляет.** Она честно пишет, что
  приём заявок не подключён. Канал (Telegram, почта, CRM) не выбран.
- **Касса выключена.** Цены не объявлены, флаг `PRICES_PUBLISHED` в
  `lib/billing/flags.ts` стоит в `false`, вместо оплаты — «В процессе
  обсуждения». Включать только после того, как сумма в каталоге API совпадёт с
  суммой, которую списывает Click (сейчас в примере `CLICK_PLAN_PRO_AMOUNT_UZS`
  — 299 000, а в каталоге Pro — 39 000).
- **Click не подключён** — ждёт договора мерчанта; для подключения на сайте уже
  есть оферта, реквизиты и контакты.
- **Оферта — черновик**, её должен прочитать юрист. `npm run check:legal`
  перечисляет, что осталось.
- **Кнопки App Store и Google Play** говорят «скоро», пока приложение не
  опубликовано. Адреса вписываются в `lib/app-links.ts`.
- **Узбекский и китайский тексты** — черновики, их должен проверить носитель.
