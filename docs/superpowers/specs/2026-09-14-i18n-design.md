# MyTamga — мультиязычность: дизайн

Дата: 2026-09-14
Статус: на согласовании
Ветка: `feat/i18n`, от `feat/theme-switcher`

## Контекст

Клиенты — из Узбекистана, Китая и США. Сайт целиком на русском: две из
трёх аудиторий его не прочтут. Мультиязычность — фундамент для следующего
подпроекта (заявки и согласие на обработку данных): согласие на непонятном
человеку языке не считается информированным.

Инвентаризация: около 85 строк интерфейса — 47 в компонентах, 11
многострочных в JSX, 28 в `lib/content.ts`, плюс 7 сообщений валидации.

## Решения

| Вопрос | Решение |
| --- | --- |
| Языки | русский, узбекский, английский, китайский |
| Узбекский | латиница |
| Китайский | упрощённый (материковый Китай) |
| Язык на `/` | cookie выбора → язык браузера → русский |
| Подход | `app/[lang]` + типизированные словари + свой `proxy`, без зависимостей |

## Не цели

- Перевод юридических текстов — их ещё нет, они появятся в следующем подпроекте.
- Кириллический узбекский.
- Домены по странам.
- Автоматический перевод во время работы сайта.
- Решение технического долга прелоадера (3 с на каждом визите) — отдельный пункт.

## Механизм

Следует бандлу этой версии Next:
`node_modules/next/dist/docs/01-app/02-guides/internationalization.md`,
`03-api-reference/03-file-conventions/proxy.md`,
`03-api-reference/04-functions/next-root-params.md`.

### Маршруты

- `app/[lang]/layout.tsx` — корневой layout переезжает сюда целиком: скрипт
  темы, прелоадер, хедер.
- `app/[lang]/page.tsx` — главная.
- `generateStaticParams` возвращает четыре языка; `dynamicParams = false`,
  неизвестный язык даёт 404 без обращения к серверу.
- Страница остаётся статической: четыре пререндеренные версии.
- Серверные компоненты получают язык через `import { lang } from "next/root-params"`,
  без прокидывания по дереву. В клиентских компонентах и Server Actions это
  не работает — туда строки идут пропсами.

### `<html lang>`

| Сегмент | `lang` |
| --- | --- |
| `ru` | `ru` |
| `uz` | `uz-Latn` |
| `en` | `en` |
| `zh` | `zh-Hans` |

### Прокси

`proxy.ts` в корне проекта. В Next 16 `middleware` объявлен устаревшим и
переименован в `proxy`.

- Путь начинается с поддерживаемого языка — пропускаем.
- Иначе выбираем язык: cookie `NEXT_LOCALE`, если значение допустимо →
  `Accept-Language` с учётом весов `q`, сопоставление по основному подтегу
  (`zh-TW` → `zh`, `uz-Cyrl` → `uz`) → `ru`. Редирект 307 на `/{lang}{путь}`.
- `matcher` — константа, исключает `_next`, файлы с расширением и `api`.
  Без этого редирект на локаль сломал бы загрузку CSS и JS.
- Разбор `Accept-Language` — свой, около двадцати строк; пакеты `negotiator`
  и `@formatjs/intl-localematcher` из гайда не нужны для четырёх языков.

## Словари

`lib/i18n/` заменяет `lib/content.ts`:

- `config.ts` — список языков, язык по умолчанию, `htmlLang`, `hasLocale`.
- `dictionaries/ru.ts` — источник формы: `export type Dictionary = typeof ru`.
- `dictionaries/{uz,en,zh}.ts` — объявлены как `Dictionary`. **Пропущенный или
  лишний ключ роняет `typecheck`**, пустая строка до продакшена не доезжает.
- `get-dictionary.ts` — `import "server-only"`, выдаёт словарь по языку.

Заголовок героя в словаре — **массив строк**: у каждого языка свои переносы.
Длина массива не фиксирована.

`PLACEHOLDER` становится ключом словаря: у каждого языка своя заглушка.

`capabilities.tsx` сейчас держит тексты внутри — они переезжают в словарь,
раз уж все секции переводятся.

## Валидация формы

`lib/lead.ts` возвращает **коды**, а не фразы: `name.short`, `name.long`,
`contact.missing`, `contact.invalid`, `company.long`, `goods.short`,
`goods.long`. Форма переводит их через словарь. Иначе китайский клиент
увидел бы «Укажите имя».

## Клиентские компоненты

Получают свои строки пропсами от серверной страницы: хедер, переключатель
темы, форма, поле ввода (пометка «необязательно»), прелоадер, герой
(`demo.tsx`), «Возможности», сцена Spline (подпись индикатора загрузки —
сейчас там осталась заглушка «Место под текст»).

## Переключатель языка

Сделан **как переключатель темы**: та же объёмная пилюля, те же материалы,
тот же бегунок с пружиной и вспышкой — только на четыре положения.

- Внутри дорожки — `RU · UZ · EN · 中文`. Код `ZH` китайскому читателю ни о
  чём не говорит.
- Бегунок стоит под текущим языком и уезжает к выбранному по той же кривой с
  перелётом, что у темы.
- **Позиция считается в процентах от ширины бегунка**:
  `translateX(calc(var(--lss-index) * 100%))`, а ширина бегунка — четверть
  дорожки. Один компонент работает и компактным, и растянутым.
- Текущий язык известен на сервере (он в адресе), поэтому позиция верна с
  первой отрисовки. Теме для этого понадобился CSS по атрибуту, здесь хватает
  серверного рендера.
- **Десктоп (`md` и шире):** компактный, в третьей колонке хедера перед
  переключателем темы, 40px в высоту, как соседи.
- **Мобильный:** растянутый на всю ширину панели бургера. В строку хедера
  четвёртый контрол не помещается: при 390px правая колонка — 163px.
- Семантика — навигация, а не радиогруппа: `<nav aria-label>` с четырьмя
  ссылками. У каждой `hrefLang` и `lang`, чтобы скринридер прочитал
  «Oʻzbekcha» по-узбекски. Текущая отмечена `aria-current`.
- Cookie `NEXT_LOCALE` пишется **только при явном выборе**, а не прокси на
  каждом заходе. Иначе коллега, открывший присланную ссылку на `/zh`, дальше
  встречал бы сайт по-китайски.
- Переход — через `next/link`. Проверка: тема сохраняется, прелоадер не
  появляется повторно, `<html lang>` обновляется.
- Кольцо фокуса на каждой ссылке; `prefers-reduced-motion` убирает перелёт и
  вспышку.

## Метаданные

`generateMetadata` по языку:

- `title` и `description` берутся из **утверждённого** копирайта героя, а не
  из заглушки. Это закрывает один блокер запуска, ничего не выдумывая.
- `alternates.languages` — взаимные `hreflang` на четыре языка плюс
  `x-default` на русский.
- `metadataBase` из `NEXT_PUBLIC_SITE_URL`, по умолчанию
  `http://localhost:3000`. Боевой домен — блокер запуска.

## Шрифты

- Узбекская латиница: `ʻ` и `ʼ` (U+02BB, U+02BC) объявлены в базовом
  латинском подмножестве Manrope и Unbounded. Проверяется рендером, что глиф
  рисуется из Manrope, а не подставляется из запасного шрифта.
- Китайский: иероглифов нет ни в одном шрифте. В конец обоих
  `font-family` добавляется системный стек: `"PingFang SC", "Hiragino Sans GB",
  "Microsoft YaHei", "Noto Sans CJK SC"`. CJK-вебшрифт весит мегабайты —
  для лендинга это не оправдано.

## Переводы

- Английский — пишу я.
- Узбекский и китайский — черновики, каждый словарь помечен
  `REVIEW(translation)`. До запуска их проверяет носитель.
- Утверждение героя переводится, но финальная формулировка на каждом языке —
  за заказчиком.

## Проверка

- `typecheck` ловит неполные словари.
- Для каждого языка: все секции на месте, верный `<html lang>`.
- **В `/uz`, `/en`, `/zh` в видимом тексте нет ни одного кириллического
  символа.** Это автоматически ловит любую пропущенную строку.
- Нет горизонтального переполнения: 4 языка × 390 / 1280 / 1680. Узбекские
  длинные слова в заголовке с `whitespace-nowrap` — главный риск.
- Прокси: `/` при `Accept-Language: zh-CN` уводит на `/zh`, cookie `en` — на
  `/en`, без подсказок — на `/ru`. CSS и JS грузятся, не уходя в редирект.
- Сборка: четыре версии пререндерены статически.
- Ошибки формы на языке страницы: пустая отправка на `/zh` даёт китайские
  сообщения.
- Переключатель языка: клавиатура, Escape, `aria-current`, тема сохраняется.
- `hreflang` в `<head>` на всех четырёх страницах.
- Тема без вспышки на всех языках.
- Тёмная тема на `/ru` совпадает со слепком вне хедера.

## Риски

- **Переполнение в герое на узбекском.** Если строка не помещается при 390px,
  у узбекского своя разбивка на большее число строк.
- **Смена корневого layout.** Если переход между языками окажется полной
  перезагрузкой, прелоадер показывался бы на каждой смене языка по 3 с.
  Решение на этот случай зафиксировано заранее: прелоадер показывается
  **один раз за сессию** (флаг в `sessionStorage`). Заодно это наполовину
  закрывает техдолг «3 с на каждом визите».
