# MyTamga — светлая тема: дизайн

Дата: 2026-09-14
Статус: на согласовании
Ветка: `feat/light-theme`, от `feat/landing-sections`

## Контекст

Сайт целиком тёмный: «тихое почти-чёрное выставочное пространство». Токены
лежат в `:root`, но механизма тем нет, а по компонентам около 55 цветов
захардкожены напрямую (`text-white/55`, `border-white/[0.07]`, градиенты) и
ещё около 34 — в `globals.css` вне `:root`.

Светлая тема **добавляется** к тёмной, а не заменяет её.

## Принятые решения

Выбраны в брейншторме, в том числе на живом рендере сайта:

| Вопрос | Решение |
| --- | --- |
| Как попасть в светлую | Тёмная по умолчанию, кнопка в хедере, выбор запоминается |
| Характер палитры | «Галерейный белый» — тёплая бумага, продолжение выставочной концепции |
| Робот | Без изменений. Проверено рендером: чёрный хром на бумаге читается |
| Герой | Светлый целиком. «Тёмный герой над светлым» отброшен: жёсткий шов |
| Кнопки | Остаются тёмными в обеих темах |
| Карточки | «Бумага с хромом»: лицо светлое, кромка — тот же живой шейдер |

## Не цели

- Следование системной теме (`prefers-color-scheme`). Отказались осознанно:
  первое впечатление у всех — тёмный герой.
- Перекраска радуги прелоадера — работает на обоих фонах.
- Перекраска `LiquidMetalButton` — тёмная в обеих темах по решению выше.
- Смешанные темы по секциям.

## Механизм

Следует гайду `node_modules/next/dist/docs/01-app/02-guides/preventing-flash-before-hydration.md`
этой версии Next.

**Отсутствие атрибута = тёмная.** `:root` сохраняет текущие значения без
изменений. Светлая задаётся `:root[data-theme="light"]`. JSX `data-theme`
не выставляет вовсе.

**Без вспышки.** В `<head>` корневого layout — синхронный инлайн-скрипт:
читает `localStorage["theme"]` и, если там `light`, ставит атрибут на
`<html>` до первой отрисовки. `try/catch` на случай недоступного хранилища.
На `<html>` — `suppressHydrationWarning`, потому что скрипт добавляет
атрибут, которого нет в серверной разметке.

Хранилище — `localStorage`, не cookie: cookie, прочитанная на сервере,
выключила бы статическую пререндерную сборку, а страница сейчас статична.

**Ловушка dev-режима.** Strict Mode в разработке перемонтирует корень и
сбрасывает атрибуты `<html>` до заданных в JSX — атрибут от скрипта
стирается. Переключатель в `useLayoutEffect` повторно применяет сохранённое
значение. В продакшене это пустая операция.

**Прелоадер** берёт фон из токена, поэтому на первой отрисовке уже в
нужной теме.

### Сведение уровней прозрачности

Сейчас в тёмной теме шесть уровней белого текста: 30, 40, 45, 50, 55, 60 %.
Они сводятся к трём токенам: `--ink-soft` (50, 55, 60 → 55), `--ink-faint`
(40, 45 → 45), `--ink-ghost` (30).

Тонкие рамки так же: `border-white/[0.07]`, `[0.08]`, `[0.09]` → `--line-soft`
(8 %).

Смещение в тёмной — не больше 5 процентных пунктов для текста и 1 пункта
для рамок, глазом неразличимо. **Это единственное допустимое изменение
тёмной темы.** Все составные токены в тёмной равны текущим значениям
побайтно.

### Контраст

Все текстовые токены светлой темы обязаны давать не меньше **4.5:1** на
`--canvas` и на `--surface` (WCAG AA для обычного текста). Исключение —
градиент `--hero-title`: это крупный текст, для него порог 3:1.

Поэтому в светлой иерархия сжата: `--ink-faint` и `--ink-ghost` совпадают.
Сделать «призрачный» уровень бледнее, не провалив контраст, нельзя.

**Порядок заметности одинаков в обеих темах:** `--ink` > `--ink-muted` >
`--ink-soft` > `--ink-faint` ≥ `--ink-ghost`. В тёмной «заметнее» значит
светлее, в светлой — темнее. Нарушить этот порядок значит поменять местами
навигацию и абзацы по весу.

## Компоненты

**Новое:**
- `components/theme-toggle.tsx` — кнопка переключения.

**Меняется:**
- `app/layout.tsx` — скрипт в `<head>`, `suppressHydrationWarning`.
- `app/globals.css` — блок светлых значений, захардкоженные цвета вне
  `:root` переводятся на токены, семантические цвета выносятся в
  `@theme inline`, чтобы писать `text-ink-soft`, а не `text-[var(--ink-soft)]`.
- `components/ui/liquid-metal-panel.tsx` — лицо карточки уходит из
  утилит-градиентов в CSS-класс на токенах `--panel-face*`.
- `components/demo.tsx` — заголовок на `--hero-title`, абзац на токене.
- Все секции, хедер, футер, форма и поле ввода — `text-white/NN` и
  `border-white/[…]` заменяются семантическими утилитами.

**Не меняется:** `liquid-metal-button.tsx`, `liquid-loader.tsx`, `splite.tsx`.

## Переключатель

- Круглая кнопка того же вида, что бургер. Третья колонка хедера получает
  обёртку `flex gap-2 justify-self-end`: переключатель слева, бургер справа.
  Бургер по-прежнему `md:hidden`, переключатель виден на всех ширинах —
  поэтому на десктопе он один занимает сейчас пустую колонку.
- Иконки солнца и луны обе в DOM, видимую выбирает CSS по `[data-theme]`.
  Иконка не зависит от React-состояния, значит не расходится при гидратации.
- Доступное имя постоянное: «Светлая тема». `aria-pressed` отражает
  состояние. Начальное значение совпадает с сервером (`false`), в
  `useLayoutEffect` оно синхронизируется с атрибутом `<html>` — до отрисовки
  и без расхождения гидратации.
- Нажатие меняет атрибут на `<html>` и пишет выбор в `localStorage`.
- Кольцо фокуса — как у остальных кнопок хедера.

## Подсветка героя

`Spotlight` рисует размытое фиолетовое пятно под курсором. На бумаге оно
грязнит фон, поэтому в светлой теме получает класс с непрозрачностью
`0.55`. Это украшение, от него ничего не зависит.

## Ограничения

- Инлайн-скрипт блокируется строгой CSP без `'unsafe-inline'`. CSP на сайте
  сейчас нет. Если появится — скрипту понадобится nonce.
- Правило проекта остаётся в силе: в `globals.css` — только цвет и форма,
  раскладка — в утилитах.

## Проверка

- **Тёмная не изменилась.** До правок снимается слепок вычисленных `color`,
  `background-color`, `background-image` и `border-color` **всех** элементов
  страницы в тёмной теме.
  После правок слепок совпадает, кроме сведения уровней прозрачности,
  описанного выше. Сравнение по вычисленным стилям, а не по пикселям:
  анимированный Spline-канвас делает попиксельное сравнение шумным.
- **Светлая без вспышки.** С сохранённым `light` у `<html>` уже стоит
  атрибут в момент первой отрисовки — проверка на сыром HTML до гидратации.
- **Выбор переживает перезагрузку** и работает в `npm run dev`, не только
  в сборке — это и есть проверка ловушки Strict Mode.
- **Контраст.** Для каждого текстового токена светлой темы вычисляется
  коэффициент на `--canvas` и `--surface`, порог 4.5:1.
- **Переключатель:** клавиатура, `aria-pressed`, отсутствие ошибок гидратации.
- **Все прежние проверки стенда зелёные в обеих темах** на 390 / 1280 / 1680.
- `typecheck`, `lint`, production-сборка.
